# 0004 — Talos Linux: immutable nodes, no SSH, config as data

- Status: accepted (cluster built 2026-05), contract migrated 2026-11-04

## Context

When the cluster was rebuilt in 2026-05, what it replaced was RKE2-shaped: mutable
nodes reached by SSH, where node state — packages, kubelet flags, container runtime
config — drifted and the fix lived in shell history. The build was also the point
at which the node contract had to be chosen, because it had to exist before the
first node did. With a conventional distribution, drift stays invisible until an
upgrade exposes it, and debugging then depends on SSH access to a host that may be
the thing that is broken.

The homelab also wanted the upgrade path to be boring: `talosctl upgrade-k8s` and
`talosctl upgrade` instead of a per-node package ritual, and a machine
configuration that is reviewed like code.

## Decision

- **Talos Linux on all five nodes** (currently v1.14.5, Kubernetes 1.36.6, etcd
  3.7.3). Immutable OS, API-driven, **no SSH and no shell**.
- **All machine configuration is data**, generated by the `talos` Terraform module
  and expressed as 1.14 config documents (`UnattendedInstallConfig`,
  `KubeNodeConfig`, `KubeNetworkConfig`, `KmsgLogConfig`, …) applied as patches per
  node. Node labels, taints, kubelet args, apiserver flags and log destinations all
  live in `patches.tf`.
- **Explicit over renderer defaults** where a default would be a silent behaviour
  change: pod and service CIDRs are stated, `workloadIsolation` is pinned off
  during the contract migration, and the MetalLB exclusion label is deliberately on
  control planes only.
- **Control planes are tainted** (`NoSchedule`) so workloads do not land on
  two-core nodes by accident. Before the taint existed, ArgoCD was placed with
  explicit resource requests and the scheduler kept it on workers anyway — a
  `nodeSelector` was never needed.

## Consequences

- **No SSH means debugging is different, not impossible.** It is `talosctl`
  (`logs`, `read`, `service`, `etcd`), the serial/console view, and logs shipped
  off-box. When the kernel dies, the log shipper dies with it — which is why
  netconsole and pstore matter more here than on a host with a disk-backed journal.
  One incident (pods stuck `Terminating`) was diagnosed by reading
  `/proc/self/mountinfo` through `talosctl read`.
- **The ingress firewall blocks by default, with one all-port allow.** Talos 1.14's
  ingress firewall was added on 2026-11-04, but the lab-LAN rule is an all-port
  allow, so etcd metrics on `:2381` remain exposed to the whole lab LAN. That is an
  accepted, written-down risk rather than an oversight.
- **Config-contract upgrades are migrations.** Moving from the 1.12 contract to
  1.14 replaced `.machine.install`, `.machine.nodeLabels` and friends with
  documents; a base config plus its replacement document is rejected by the node.
  The migration was staged (validate `--strict`, then apply) and is documented as a
  procedure, not a version bump.
- **The Terraform state now holds cluster identity.** Machine secrets and the
  generated kubeconfig/talosconfig live in the `talos` state, which is why state
  encryption and the apply guard (ADR 0001) are part of this decision's blast
  radius rather than a separate concern.
- **A copied label becomes an outage.** The 1.14 renderer puts
  `node.kubernetes.io/exclude-from-external-load-balancers` on control planes but
  not workers. Copying the control-plane label set to workers made MetalLB exclude
  every node and withdraw all VIPs (2026-11-04). Configuration that is "the same
  for both" is not automatically safe.
